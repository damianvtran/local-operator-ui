## The nine macOS-only tests, and why skipping them is not a pass

They drive a path that is macOS-only BY CONSTRUCTION, not incidentally:
`prepareManagedPython` writes `platform: "darwin"`, takes its lock through
`/usr/bin/shlock`, and `verifyMachO` refuses a seed with no Mach-O in it while running
`codesign`/`otool` over every one it finds - so its seed fixture has to be a real thinned,
ad-hoc-signed binary (lipo + codesign). `finalContainerChecks` needs `ditto`, `hdiutil` and
`lipo`. Each of the nine now calls `skipUnlessDarwin`, which is the first statement of the
test, before any fixture work, and the skip NAMES the missing tool.

```
$ # CI, Desktop Tests on ubuntu-latest, the skips this branch owns
$ grep -oE "# SKIP [^\"]*" log | sort | uniq -c
     10 # SKIP macOS only: preparing an environment takes the shlock lock and verifies every Mach-O in the seed with codesign and otool, so the fixture seed is a real thinned, ad-hoc-signed binary (lipo, codesign)
      4 # SKIP macOS only: the container gate builds archives with ditto, mounts images with hdiutil and reads an app's architecture with lipo
      2 # SKIP macOS only: the image is built and mounted with hdiutil, which this platform does not have
      2 # SKIP macOS only: the archive is built with ditto, which this platform does not have
```

The log carries the TAP report twice, so each count is 2x the number of tests:
5 + 2 + 1 + 1 = the nine guards. The other 15 skips are the repository's own pre-existing
conventions (`macOS only`, `no local-operator on this machine's PATH`, `a shallow clone has
no ancestor of HEAD to check`), which is why CI reports 24.

Making the guard complete rather than blanket took two moves, so that coverage on Linux was
not simply lost:

- `artifactArch`'s three filename cases moved into their own test that runs on every
  platform, leaving the container test only the half that needs `lipo`.
- The contract review R8 is about - a published selection answers ready/missing/unprepared
  instead of THROWING - is now also asserted on a hand-built selection
  (`runtimes/<id>-<uuid>`, `environments/<id>-<uuid>`, the record and the pointer), which
  needs no toolchain, so the verdict stays covered where the provisioning tests skip.
