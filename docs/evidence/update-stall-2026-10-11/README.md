# The 2026-10-11 updater stall: 26 minutes of silence, and the ends this fixes

The operator started an in-app update to 0.34.9, the window vanished at
23:53:08, and NOTHING happened for 26 m 48 s (the spawner's own wait, a
second longer). Both logs stopped mid-sentence -
the quit's own stages all logged complete ("Owned backend generation stopped",
"App is about to quit") - and the installer this app had spawned waited,
unlogged, on an app pid that stayed alive with no window. The operator ended it
by hand (`kill -TERM 81333`), and ShipIt exec'd 0.4 s later. The install itself
was healthy: swap, relaunch and the successor's success verdict all followed in
seconds once the pid was gone.

This directory holds the incident verbatim, the pre-fix reproduction, the
post-fix runs, and the numbers the fix's bounds derive from.

## The incident, from the machine's logs

[incident-timeline.txt](incident-timeline.txt) is the verbatim record:
the quit's last stages, the installer spawn and the watchdog line at
23:53:07-08, the 26-minute gap with zero lines in either log (26 m 49 s from the
spawner's first line), the
`kill -TERM` resolution, and the install that completed 20 seconds later.
The one line that says what did happen is the spawner's absence of any line
at all.

## Two root causes, two fixes

1. **The spawner's wait was unbounded and silent.** `update-shipit.ts`'s script
   was `while kill -0 "$1"; do sleep 0.2; done` - no timeout, no log. The fix
   is a bounded, escalating ladder: first grace (60 s, derived from the 1.3-4 s
   a good quit measures) -> SIGTERM, only after `ps` still names the app ->
   second grace (20 s) -> SIGKILL -> settle -> start the installer REGARDLESS.
   Every stage is one timestamped line in the installer's own log, and a pid
   whose command line no longer names the app is never signalled.
2. **The quit had a phase with no terminal.** Between `before-quit`'s
   synchronous return (Electron closes the windows) and `will-quit` there is no
   bound, no terminal and - until now - no log. `quit-exit-deadline.ts` gives it
   one: a hard deadline armed in `before-quit`'s synchronous part, derived from
   the bounds in front of it (`SESSION_COOKIE_QUIT_BUDGET_MS +
   QUIT_CLEANUP_FAILSAFE_MS + margin` = 121.5 s on the incident build), with a
   phase marker so the fired line NAMES the stage, and released only by the
   quit's one cancellation. A SIGTERM during a quit is now a deterministic,
   logged exit too - the escalator's contract.

Plus the honesty half: [post-fix-escalation.txt](post-fix-escalation.txt)
shows the watchdog speaking while the app is still up ("Waiting for Local
Operator to close... (waiting N s)", then the fallback hint), and the hard
bound no longer claiming "Local Operator is opening again" on the arm where it
exits without launching. And cache hygiene:
[cache-residue.txt](cache-residue.txt) measures the ~345 MiB double retention
(`update.zip` and `pending/<artifact>.zip` are byte-identical, sha256
`62e4557...`), which `reapUpdaterCache` now reduces to one artifact's worth
after a settled install - the differential base - and never while an install
may still be reading it.

## The pre-fix reproduction

[pre-fix-repro/](pre-fix-repro/) keeps the shipped old script

## The post-fix runs

[post-fix-escalation.txt](post-fix-escalation.txt): the SAME scenario against
the shipped new script, generated by `buildInstallerSpawn` itself. Run 1 (a
windowless carrier, production graces): the ladder asked the app to stop at
60 s, the app exited, and the installer started at 60.1 s. Run 2 (a target that
ignores SIGTERM, short graces): SIGTERM at 5 s, second grace, SIGKILL at 8 s,
installer at 9.6 s. Both runs: every stage logged, both bounded.

## What was measured on this machine, and what was not

- Measured here: the incident lines (both logs), the cache residue and its
  byte-identity, the pre-fix stall shape, the post-fix runs, and the targeted
  suites ([test-outputs.txt](test-outputs.txt)).
- NOT producible on this machine: a real in-app update of the operator's
  installed app. The fix's quit-side terminal (`index.ts`) cannot be exercised
  by a headless test - `index.ts` has no bootable harness in this suite - so its
  wiring is pinned at the source (`scripts/window-mode.test.mjs`,
  `scripts/launcher-watch.test.mjs`) and its deadline object is driven directly
  (`createQuitExitDeadline`, real timers). The escalator, the watchdog's
  notices, and the cache reap ARE driven for real (real processes, real
  scripts); the operator's app and `/Applications` were never touched.
- One pre-existing failure is recorded rather than hidden:
  `update-robustness.test.mjs`'s "the operator's own install is classified..."
  fails on THIS machine because the `local-operator` shim now resolves into a
  lop generation with no distribution markers. It fails identically with every
  change in this branch stashed - see [test-outputs.txt](test-outputs.txt).
