# The self-seal invariant, the field break, and every repair

Measured on this machine, 2026-09-14, against the signed 0.22.2 disk image mounted
at `/Volumes/Local Operator 0.22.2-arm64` (source
`~/Downloads/local-operator-ui-0.22.2-arm64.dmg`) and copies taken out of it, plus
a locally packaged build of this branch. Every block below is a command and its own
output, in the order it was run.

What it establishes, in the same order:

1. the operator's machine state, read-only: the venv that is built on the
   installed bundle, the marker the 0.22.2 install left, and the log lines that
   say no packaged instance ever came back;
2. the shipped artifact is born writable, and one unguarded interpreter run in it
   breaks its seal exactly as the field install broke - including the same
   `webbrowser.cpython-312.pyc`;
3. the app's own heal takes that break back to `valid on disk`, and the build
   step is what stops it recurring, at the cost measured for the start-up probe;
4. the app-managed venv is built on the interpreter inside the installed bundle,
   which is the propagation path, and the venv-side guard closes the part of it a
   guard can close;
5. the release gate fails the shipped artifact and passes a sealed build of this
   branch;
6. the contract tests fail when the guards are removed, and for a new spawn site
   that omits them.

## 3. What the start-up probe costs

The probe the start-up repair pass runs is the same `codesign --verify --deep` the
pre-flight runs, over the whole bundle, so it is deferred 15 s past window creation
and unref'd rather than run in the launch path.

## What could not be produced here, and where it is covered

- There is no Developer ID identity on this machine (`security find-identity -v -p
  codesigning` -> `0 valid identities found`), so a locally packaged build cannot
  pass the three signing checks in section 5; they fail with `code has no
  resources but signature indicates they must be present`, which is what an
  unsigned local build looks like. The positive direction on real signed artifacts
  runs in `publish.yml`.
- The failure is not only the UI's: recorded from a read-only trace of the
  operator's wake job (`com.local-operator.wakes`), the installed app's broken
  seal plus its quarantine attribute made the OS refuse to load
  `Contents/Resources/python_aarch64/lib/libpython3.12.dylib` ("library load
  disallowed by system policy"), which took that job's sessions out for the
  morning. It is recorded rather than reproduced here: the installed copy it was
  about no longer exists on this machine.
