## 4. The gate's own reading, through Electron itself

The fix uses `net.isOnline()` - "this machine believes it has no network", which is
exactly the dark-wake state above (`node_modules/electron/electron.d.ts:10311`).
Read for real, through Electron 44.3.0, by a two-line script that creates no window:

    // probe.js
    const { app, net } = require("electron");
    app.dock?.hide();
    app.whenReady().then(() => { console.log("net.isOnline():", net.isOnline()); app.quit(); });

$ npx electron probe.js --user-data-dir=/tmp/lo-net-probe/ud

net.isOnline(): true

TRUE is the expected reading on a machine with a working network; what the gate
acts on is the FALSE one, which is the dark-wake window's state and which cannot
be manufactured here. The gate's DECISION (skip the attempt, report nothing, leave
the verdict `unavailable`) is exercised against the shipped module in
`scripts/update-robustness.test.mjs` ("a check the machine has no network for
spends no request").

## 5. What the fix does about it

- `UpdateService.networkIsReachable()` gates the app-channel fetch and the server
  channel's two reads: a machine that reports no network spends NO request and
  reports nothing, and the verdict stays `unavailable` (never `current`, never
  "nothing newer").
- `powerMonitor.on("resume")` arms ONE check `POST_WAKE_CHECK_DELAY_MS` (20 s)
  later - past the ~12 s association the log above shows, and far inside the next
  five-minute tick - so the tick that lands on the wake instant is not the only
  one the machine gets. One timer: a second resume leaves the armed one alone.
