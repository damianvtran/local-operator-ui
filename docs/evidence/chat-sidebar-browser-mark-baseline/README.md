# The per-row browser mark, before it was removed

The BEFORE half of a deletion. The operator asked for the corner browser control on
every chats-sidebar row to go, and a deletion's evidence is the frames of what went:

> "I don't think we need a browser button for each chat row in local-operator-ui, can
> you remove that? Especially since we're going to have a pin icon that should show up
> on hover, it takes up too much space for a button that would be infrequently used."

**That reverses the ask this control was built for**, and the reversal is stated rather
than left implied: design R2 is titled "a corner affordance on every conversation row",
the commit that made it unconditional (`3996c3749`) records the operator's ask as "a
corner tab on EACH conversation", and `docs/design/sidebar-conversation-browser.md`
carries a superseded note naming both asks. The mark, its stories, its own
`docs/evidence/browser-conversation-mark/` set, its `renderer-driver` scene and its
contrast-contract rows are deleted with it.

## What produced these frames

Captured on **unmodified `origin/main` at `10926b782`** — the head this branch was cut
from — in its own worktree, against a Storybook dev server, with the same story files,
the same fixtures and the same viewports as the sets these frames are read beside:

```sh
# in a worktree of unmodified origin/main at 10926b782
npx storybook dev -p 6042 --host 127.0.0.1 --no-open --disable-telemetry
node scripts/capture-evidence.mjs --only=chat-sidebar-status-feed--completion-unseen \
  --themes=<the twelve the sweep uses> --allow-backend http://127.0.0.1:6042
node scripts/capture-evidence.mjs --only=chat-sidebar-status-feed--browser-marks \
  --themes=<the twelve> --allow-backend http://127.0.0.1:6042
node scripts/capture-evidence.mjs --only=chat-sidebar-current-row--bound-row-current \
  --themes=<the twelve> --allow-backend http://127.0.0.1:6042
# the three directories the runs wrote were moved here under the state names below
```

`--allow-backend` is passed because the operator's own backend is running on this
machine (`127.0.0.1:1111`) and none of these three stories talks to it: each stubs its
own transport, which is what every committed frame of both sets depicts.

**It cannot be regenerated by a sweep.** A sweep captures the CURRENT tree, and no tree
after this branch draws the mark: these frames are the only pictures of the control the
removal takes away. Declared as a `supplementary` set for that reason, so
`clearSweptFrames` preserves it and the sweep's own count stays honest — the arrangement
`chat-sidebar-current-row-baseline/` and `chat-sidebar-status-feed-baseline/` already
use.

## What these frames do and do not show

- **They show the control, its width and its badge, on a real row.** The Globe is at
  the end of every `mark-on-every-row` title, and `mark-populated` carries the
  count-and-badge cascade. What the same row looks like with it gone is the sibling
  set's frame for the same story, which is the after half above.
- **They do not show a `· binding` row or a current row WITH the mark**, and no frame
  can: those arrangements were drawn only by the mark's own deleted story specimen
  (`browser-conversation-mark--on-both-grounds`, `--trailing-statement`), whose
  `docs/evidence/browser-conversation-mark/` set went with the control. The
  `bound-row-current/` pair here is the honest substitute for the arrangement: it is
  the row shape the operator named, photographed on both trees, and it is unchanged.
- **They are not a width measurement.** The reclamation this change is about is the
  24px control plus its gap on every title; the claim is read off the two halves side
  by side (`mark-on-every-row/` against `chat-sidebar-status-feed/completion-unseen/`)
  rather than off a number in this file. The earlier set's own `slot-cost` pair, which
  measured it, was an argument for the control and is deleted with its conclusion.
- **The themes are the twelve the sweep uses**, which is what makes these frames
  comparable with the sets they are read beside rather than with the fifty-nine the
  registry carries.

## The measurements, because "unchanged" is a claim until it is a number

- **`bound-row-current`: the pair is the same picture.** Re-captured on this branch,
  the twelve committed frames came back within **172–2,196 px** of their bytes (0.04–0.5%
  of a 436,800-px frame, worst on `radient`), and the before half here differs from the
  after half by at most that same **2,196 px** — the largest delta of the twelve. That
  band is this machine's glyph rasterisation and not a moved element: a frame whose
  CONTENT changed on this branch moves **18,366–48,659 px**, which is what the same
  re-capture measures on `chat-sidebar-status-feed/completion-unseen`, where the removed
  control's readout line really did go. Nothing in this pair was re-committed: the
  committed bytes stand, because a jitter band is not a change.
- **The after half of `mark-on-every-row` moved by what the removal is.** Its twelve
  frames changed by 18,366–48,659 px (4.2–11.1%), and the difference image is the
  readout block alone: the `Browser marks:` line and the lines below it, one line row
  higher. The rows themselves are unchanged on that pair — the committed frame was
  already drawn without a Globe — which is exactly why the BEFORE capture above, taken
  on `origin/main`'s own tree, is the only picture of the control this set could carry.
