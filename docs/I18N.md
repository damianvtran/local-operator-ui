# Contributing localized desktop copy

Use this HOWTO for desktop product-copy changes, not as proof of programme
completion. The shared contract is the core repository's
[HOWTO](https://github.com/damianvtran/local-operator/blob/532fd42d46a5f4b0930f252f2bc33ee517628c91/docs/I18N.md)
and [RFC §§2, 4, 6](https://github.com/damianvtran/local-operator/blob/532fd42d46a5f4b0930f252f2bc33ee517628c91/docs/design/i18n.md).
The drafting source is UI commit `2461cfa3f3beaa1124727a9de93dfe01c4381b0d`;
recheck current source before implementation. The linked sources describe contracts, not execution receipts.

## Follow the single language owner

1. Use General Settings' single language picker (`GeneralLanguageSetting`).
   [Native endonyms](../src/renderer/src/features/settings/components/setting-control.tsx)
   identify languages; representative country flags are
   decorative, not country preferences or coverage promises. `auto` follows the
   backend OS resolver. The [write seam](../src/renderer/src/features/settings/components/language-dialog.tsx)
   is `settings.edit` for `language`, then
   renegotiation; do not introduce a second interface preference.
2. Resolve explicit config → `LOP_LANG` → backend OS → `en`, then apply backend
   shipped eligibility. A recognized but ineligible winning tag falls back to
   English, not the next preference. Before backend negotiation, use the existing
   device-language → English bootstrap; after negotiation backend truth wins.
   Do not persist a localStorage override or use test-only `setLocale()` as one.
3. Keep model reply language separate from catalogue copy. The English
   preferred-language instruction is captured once per main-session stable
   prefix and subagent spawn; context may override replies. Setting changes
   affect the next prefix/session, not a cached prefix mid-turn. Technical and
   model-facing documentation/prompts stay English; rendered product copy is keyed.

**Snapshot dated 2026-10-15; recheck at integration:** UI commit
`2461cfa3f3beaa1124727a9de93dfe01c4381b0d` has only `en` and `fr` catalogue
directories. Recheck `src/i18n/catalogues/` before integrating these instructions.
Core commit `532fd42d46a5f4b0930f252f2bc33ee517628c91` recognizes eight tags (`en`, `fr`, `es`, `zh-CN`,
`ru`, `vi`, `ur`, `hi`); its runtime-eligible set is six (`en`, `fr`, `es`, `ru`,
`vi`, `hi`). None is proof that every UI namespace is translated, audited,
rendered, activated or released. Source-staged directories alone change no gate.

## The main process speaks the same language

Main raises its own notifications now (`ui.notices.main.*`: the update-hold
notice, the site-approval banner and the relaunch watchdog's five messages), so
it needs a locale of its own. The rules, in the order the sources win:

1. **The backend's resolved tag**, read through the SAME configured transport
   the renderer uses (`{ op: "capabilities" }`). `src/main/main-locale.ts`
   refreshes on backend start, on a config frame whose `changed_keys` contains
   `language`, and after a `settings.edit`/`settings.reset` of that key. The
   frame is a hint, not the value: every refresh re-reads, so a foreign writer
   cannot pin a tag of its choosing.
2. **The device**, read from Electron's own `getPreferredSystemLanguages()` →
   `getSystemLocale()` → `getLocale()`. Deliberately NOT `navigator.language`,
   which under Node follows `LANG`/ICU instead of the macOS preferred list. Both
   readings are structurally validated (`isLanguageTag`) before they reach ICU.
3. **English**, the store's own default, when neither can answer.

A failed read (throw, non-200, malformed envelope) keeps the previous locale and
logs no response values. A backend WITHOUT `features.i18n` falls through to the
device, exactly as the renderer's `resolveLocale` does.

**The launch hold is the exception with a record.** It runs before a window and
often before a backend is reachable, so the pending-install marker carries the
backend-resolved tag the quitting process had (`PendingInstallMarker.language`,
optional and validated on read). A marker without it is pre-version: the hold
falls back to the device reading, never to re-parsing `config.yml`. The marker is
a record for that one path, not a second persisted preference - nothing reads it
back as a choice.

**The watchdog script carries translated sentences as DATA.** It outlives the
app, so `buildWatchdogPlan` resolves the five messages from the catalogue at
build time and passes them in the script's environment. The script never
interpolates a translation into shell source; the two messages with the elapsed
wait become `printf` formats with every literal `%` escaped and `{elapsed}` as
the one conversion. A sentence with quotes, backticks or `$(...)` prints as
text.

**What this does not claim.** Copy added in English is English until the
translator/delta-audit round lands it everywhere; a legacy marker cannot be
retroactively localized; and a notification emitted before the first
capabilities answer settles speaks the device reading, not the backend's. The
device tag is kept verbatim (renderer parity), so `t()` still falls back to
English where no bundle matches it - `fr-CA` is not a `fr` bundle hit.

**Retained orphan keys.** When two merges key the same sentence in different
namespaces, the losing namespace's entries are kept until an audited removal
round. They are not dead-code evidence: removing translated, receipt-bound
values is itself an audited change, and a quick unaudited delete is the worse
failure. The current example is 22 `ui.common.*` entries superseded by
`ui.notices.*` call sites; their removal is deferred, not forgotten.

## Add or change product copy

1. Own a small namespace, including theme/layout copy. Give each message an
   immutable semantic `ui.<area>.<name>` key in
   `src/i18n/catalogues/en/ui.<area>.json`. Add an English sibling
   `ui.<area>.context.json` with role, tone, width and placeholder context where
   needed. Do not translate identifiers, commands, flags or machine tokens.
2. Use ICU arguments and the actual locale's CLDR plural/select categories,
   not concatenated fragments. Render through `t()` and existing React bindings
   in `src/renderer/src/shared/i18n/`; use existing locale-aware formatters.
3. Generate `src/i18n/keys.gen.ts`; never hand-edit generated types. Its parameter
   map and [`t()`'s two overloads](../src/i18n/messages.ts) reject
   [four cases](../scripts/i18n/fixtures/typed-keys/call-sites-negative.ts): unknown key, wrong argument
   type, missing required arguments, and arguments on a parameterless key.
4. Use the existing developer commands below from the repository root. They
   are instructions, **not commands executed for this draft**; no locale CLI exists.

```sh
node scripts/i18n/generate.mjs
pnpm check-i18n
pnpm check-types
```

[`check-i18n`](../package.json) checks generator freshness,
[string scanning](../scripts/i18n/check-strings.mjs), the audit ledger,
[context parity](../scripts/i18n/context-parity.mjs) and
[manifest-backed coverage](../scripts/i18n/check-coverage.mjs): every language
marked `supported` in `i18n/languages.json` must carry every English key, and
the known gaps in `i18n/coverage-allowance.json` are exact and shrink-only. That
is not advice: a pull request touching `src/i18n/**`, `i18n/**` or
`scripts/i18n/**` runs this command in CI's `Language Coverage` job, with the
coverage half compared against the pull request's base, so an allowance that
grows fails the pull request rather than a review comment.
The literal ratchet blocks every finding against `i18n/baseline.json`: there is
no advisory scope, and a file with counted literals and no recorded entry fails
rather than starting at zero, so a new file is covered from its first commit.
Lower touched ceilings with `node scripts/i18n/check-strings.mjs --update
<paths>`; never raise a baseline by hand instead of extracting copy. A reviewed
`node scripts/i18n/check-strings.mjs --init --force` capture prints every
added, raised, lowered and pruned entry, which is the diff to review. The only
exemptions are narrow reasoned entries in `i18n/allowlist.json` or `i18n: ignore`
comments, never broad scanner bypasses.

## Merge a shared new English catalogue by hand-union

When two PRs each create the same new shared catalogue (for example
`src/i18n/catalogues/en/ui.common.actions.json`) with disjoint keys, the
second PR to merge must hand-union the two copies. There is no merge driver
for these files, and resolving with `--ours` or `--theirs` silently drops
the other side's keys. No existing gate catches a dropped English key:
`generate.mjs --check` only proves the generated map matches the current
catalogues, never the other side of the union.

Union at the raw-line level: copy the missing `"key": "value"` lines into
the merged file as text. Never round-trip either side through a JSON
serializer (`json.dump`, `JSON.stringify` over the whole file) — either
round-trip rewrites bytes it did not need to touch: Python's `json.dump`,
for example, re-encodes a literal right single quotation mark as the
six-character escape `\u2019`, while JavaScript's `JSON.stringify` keeps
it literal, and both churn existing lines in the process.

This is a merge-time check, not a CI gate: an extraction legitimately
removes keys, so a standing "no key removed" rule would false-positive on
ordinary PRs. After hand-unioning, before merging, run the parity tool from
the repository root with the PR's pre-merge head SHA and paste its output
on the PR under `### Merge-time en-parity evidence`:

```sh
node scripts/i18n/catalogue-union-parity.mjs \
  --pr <pr-number> --head <merged-head-sha> --old-head <pre-merge-head-sha> \
  --file src/i18n/catalogues/en/ui.common.actions.json \
  --file src/i18n/catalogues/en/ui.common.actions.context.json
```

`--base` defaults to `origin/main`; add one `--file` per unioned file
(a catalogue and its `.context.json` sibling). The tool reads all three
versions with `git show` (nothing is checked out) and exits non-zero if
any key from either side is missing from the merged head, or any shared
key's value changed. A key the two sides disagree on is a real conflict:
resolve it by hand and say so on the PR rather than silencing the tool.
A run with identical `--head`/`--old-head` is refused (exit 2) because it is vacuous: it proves only that the pre-merge tree equals itself.

## Add or extend a locale

1. Read the core glossary and native locale style guide before translating;
   settle native terminology, register, kept-English names, digits and fit.
   Mirror carried namespaces under `src/i18n/catalogues/<locale>/`, preserving
   keys, placeholders and required CLDR categories. Missing inputs are a stop,
   not permission to improvise an audit.
2. Regenerate before a backend tag can reach the UI. The [generator](../scripts/i18n/generate.mjs) discovers
   **every present locale directory**, emits `bundledCatalogues`, and aliases
   English to `bundledEnglish`. At the dated source pin above that means only `en`/`fr`; recheck at integration.
   Do not manually register generated bundles or claim that a new directory
   activates a language; coordinate backend eligibility and rollout separately.
3. Preserve lookup order: served/registered catalogue → present-locale bundle →
   bundled English. [`sourceTagFor()`](../src/i18n/messages.ts) selects formatting/plural rules from the
   catalogue that answered, so English fallback uses **English**, not target,
   rules. Missing namespaces are not evidence of whole-locale completion.
4. Delegate translation to an LLM translator and complete review with a
   different, independent auditor; never self-audit or use a translation
   API/SDK/MT service. Record actual agent, served model and fallback, dates,
   English/target/context hashes and the glossary/style-guide revision or hash.
   Require native glossary/style conformance, placeholder/CLDR checks,
   pseudo-localization, RTL and rendered fit evidence where applicable.
   High-visibility groups require a second independent audit.

## Retain checkable audit records

Use the approved programme retention practice below. Its documentation integration
is pending; this draft does not claim additional UI checker enforcement or new UI
functionality. Keep immutable records under the canonical
`i18n/audits/evidence/<locale>/<namespace>/<audit-id>/` root. A declared
repo-specific equivalent is allowed only when a tracked manifest maps it;
do not fragment evidence across sibling roots or rename existing bundles.

Retain `record.json` and necessary companions with locale, namespace, date,
actual auditor agent/session/model and independence, English/context/target
paths and SHA-256 hashes, findings/status, and artifact paths/hashes. Keep
notes explicitly distinct from execution logs; never invent command output.
Keep the two repository ledger contracts distinct:

- **This UI:** [`i18n/ledger.json`](../i18n/ledger.json) uses `status: "audited"`
  and `auditors[]`. Each auditor's `findings` is a severity-count object
  `{blocker, major, minor, nit}`, not a scalar. The
  [checker](../scripts/i18n/ledger-check.mjs) and
  [shared rules](../scripts/i18n/ledger-rules.mjs) verify counts against immutable
  namespace-scoped receipts, bind English **and target** hashes plus receipt
  hashes, and require independent auditor instances. Passing results are
  `clean` or `clean-with-findings` with zero blockers/majors; actual minor/nit
  counts remain recorded. Keep mandatory receipt paths under `i18n/receipts/`;
  a tracked manifest can map these existing artifacts to the canonical evidence
  root without moving receipts or changing the UI schema/runtime.
- **Core only:** RFC §6's scalar `auditor.findings` counts unresolved
  BLOCKER/MAJOR findings. Do not transplant that field shape into this UI.
- **Programme documentation convention:** where a ledger schema has a note/path
  field, reference the tracked record there and keep the **entire note <=280
  characters**. The pinned UI checker has no 280-character check; do not invent
  a UI per-row note field or pretend this convention is enforced by it. Where
  the schema lacks such a field, retain the link in the tracked manifest.

Preserve actual MINOR/NIT IDs and dispositions in artifacts and any supported
note field. Zero blockers is not zero total findings; never manufacture an
auditor result.

Scratch is temporary work in progress, never the artifact of record. Immediately
attach untracked temporary outputs to the project or otherwise make them durable;
close temporary references when the tracked commit lands. Never delete the only
ignored staging copy before that commit exists. If an original was lost, state
that loss and label the new record **REPLACEMENT**, with its own date: never
backdate or present it as an original/historical recreation. Preserve existing
authority-scope addenda and historical records; a recorded five-locale authority
exception is not a new audit kind or a waiver of unchanged gates.

## Validate the claim, not just the source

- [CI's Desktop Tests job](../.github/workflows/ci.yml) has a **50-minute** timeout and runs
  `pnpm test:desktop` once through `scripts/run-desktop-tests.mjs`, with the
  existing default concurrency governor in `scripts/desktop-test-concurrency.mjs`.
  Keep its defaults; do not widen parallelism. CI fails closed for absent pass
  counts, fewer than 60 passing tests, nonzero failures or a nonzero suite exit.
  Historical 35-minute references do not describe another visual engine.
- The existing plain-JavaScript QA artifact records `out/build-provenance.json`:
  requested head, checkout/source commit, source/scripts tree IDs, per-file hashes
  and workflow/run identity. It requires `main/index.js`, `preload/index.js` and
  `renderer/index.html`, and rejects `.jsc`/`.node` artifacts. This provenance
  makes source identity checkable; it is not compiled-native or rendered proof.
- IPC fixtures and source-only checks do not prove native rendering. Before
  six-locale UI claims, obtain actual English controls and before/after frames,
  font/fallback/geometry measurements, independent design and changed-flow UX
  review for the six eligible locales. Use only the harness browser tool for
  page interaction/screenshots; no custom Chrome/rig/browser engine.
- Keep holds and incomplete evidence explicit. Source-staged copy, metadata or
  a historical audit does not prove current full coverage, compiled-native
  behavior or release. Preserve historical records; no earlier pass waives a
  new scope's independent audit and security gates.

## Ownership and dependencies

UI contributors own catalogue/context changes and generated keys; the backend
owns eligibility and language resolution; independent auditors own verdicts.
Use the existing pnpm lockfile and dependency tree for later execution. This
docs-source draft needs no dependency installation, build or test dispatch.
Normal integration, independent review/QA and publication gates still apply.
